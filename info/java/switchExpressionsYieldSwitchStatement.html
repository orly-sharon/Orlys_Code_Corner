Switch Statement ו-yield (החל מ-Java 14)

החל מגרסה Java 14 ישנה מהפכה במבנה ה-switch המסורתי. מעבר משימוש בו כ-Statement (פקודה שמבצעת פעולות) לשימוש בו כ-Expression (ביטוי שמחזיר ערך ישירות).

יתרונות Switch Expressions (חדש - Java 14 ומעלה) לעומת Switch Statement (ישן - Java 13 ומטה).

1. אין Fall-through (אין זליגה אוטומטית)

ב-Switch Statement (ישן): אם שכחנו לכתוב break בסוף case מסוים, הקוד המשיך לרוץ אוטומטית לתוך ה-case הבא (תופעה שנקראת Fall-through). זו הייתה אחת הסיבות הנפוצות לבאגים.

לדוגמה קטע קוד עם הגישה הישנה:

String dayType = "SATURDAY";
String message;

switch (dayType) {
    case "MONDAY":
    case "TUESDAY":
    case "WEDNESDAY":
    case "THURSDAY":
    case "FRIDAY":
        // This runs for weekdays
        System.out.println("Processing a standard workday...");
        message = "Weekday";
        break; // MANDATORY: Without this break, code would leak into the next case!

    case "SATURDAY":
    case "SUNDAY":
        // This runs for weekends
        message = "Weekend";
        break; // MANDATORY: Without this break, code would leak into default!

    default:
        // This runs if no other case matches
        System.out.println("Invalid day provided.");
        message = "Unknown";
        break;
}

System.out.println("Result: " + message);

Switch Expressions (חדש):

לדוגמה קטע קוד עם הגישה החדשה:

String dayType = "SATURDAY";

String message = switch (dayType) {
    case "MONDAY", "TUESDAY", "WEDNESDAY", "THURSDAY", "FRIDAY" -> {
        // This block runs ONLY for weekdays and exits immediately afterwards
        System.out.println("Processing a standard workday...");
        yield "Weekday";
    }
    // This runs for weekends
    case "SATURDAY", "SUNDAY" -> "Weekend";

    default -> {
        // This only executes if none of the above match
        System.out.println("Invalid day provided.");
        yield "Unknown";
    }
};

System.out.println("Result: " + message);

2. קיבוץ ערכים בשורה אחת (Multiple Constants)

התחביר החדש מאפשר לרכז מספר תנאים שונים שמבצעים בדיוק את אותה הפעולה, תחת שורה אחת מופרדת בפסיקים.

 
case "MONDAY", "FRIDAY", "SUNDAY" -> 6;

ולא:


    
case "MONDAY":

      case "TUESDAY":

      case "WEDNESDAY":

      case "THURSDAY":

      case "FRIDY":

3. חובה לכסות את כל האפשרויות (Exhaustiveness)

כאשר משתמשים ב-Switch Expressions (חדש), הקומפיילר דורש שהקוד יכסה את כל הערכים האפשריים מבחינה לוגית, אחרת הקוד לא יתקמפל, תתקבל שגיאת קומפילציה.
אם נכתוב switch על Enum, הקומפיילר מצפה שנכסה את כל הערכים האפשריים של אותו Enum.
אם מדובר במשתנה רגיל (כמו String או int), חובה לכלול תמיד סעיף default שיסגור את כל המקרים הבלתי צפויים.

4. ערך החזרה אחיד מכל ה-Cases

מכיוון שמשתנה מקבל את הערך מתוצאת ה-switch, כל ה-case-ים כולל ה-default חייבים להחזיר את אותו סוג טיפוס (Type).
אי אפשר ש-case אחד יחזיר String ואחר יחזיר int. הקומפיילר ידרוש עקביות במשתנים המוחזרים.

5. שילוב עם שגיאות (Exceptions)

בתוך case בין אם בחץ או בתוך בלוק עם yield, מותר לזרוק שגיאה Exception. אם משהו לא תקין. הקומפיילר חכם מספיק כדי להבין ששגיאה שנזרקת עוצרת את הריצה, ולכן היא לא פוגעת בדרישה להחזיר ערך תקין.

int val = switch (input) {
    case 1 -> 10;
    default -> throw new IllegalArgumentException("Invalid input: " + input);
};
⚠️ שימו לב!

כאשר עוברים לJAVA 14 ומעלה, יש נטייה להתבלבל בגישה הישנה, לגישה החדשה. ולכן אם נכתוב בטעות RETURN באמצע ה switch נעצור את כל המטודה ולא נמשיך הלאה במקרים האפשריים.

⚠️ דוגמה לשימוש לא נכון! 
// Buggy implementation using return
public static String evaluateStatusBuggy(String status) {
 String message = switch (status) {
 case "ACTIVE" -> {
System.out.println("Executing logic for ACTIVE status...");
 // BUG: 'return' exits the ENTIRE evaluateStatusBuggy method immediately!
 // It does NOT just return a value to the switch expression.
 return "Accidental early exit!";
}
 default -> {
yield "Unknown status.";
 }
};
// This line is dead code for "ACTIVE" because the method already returned above return message;
}

ההבדל בארכיטקטורה (Scope & Context):

  • מתודה היא בלוק קוד ראשי שמסתיים תמיד עם return.
  • switch עם בלוקים {} בתוך case הוא למעשה בלוק מקונן (Nested Block) שיושב בתוך מתודה.

כאשר מפתחים משדרגים גרסאת JAVA ורואים סוגריים מסולסלים {} בתוך ה-case, ההרגל לפרש זאת אוטומטית כמו מתודה קטנה, ולכן האינסטינקט הראשוני הוא לכתוב return כדי להחזיר את הערך.

מה קורה בפועל כשמשתמשים ב-return בטעות?

מילת המפתח return אומרת ל-Java: "תעצרי הכל, צאי מיד מהמתודה הנוכחית וחזרי למקום שבו קראת לה".
כתוצאה מכך, הקוד שאמור לקבל את תוצאת ה-switch (במקרה שלנו המשתנה message) מעולם לא מקבל כלום, והשורה שאחרי ה-switch במתודה הופכת ל Dead Code, קוד מת לעולם לא נגיע לשם.

התפקיד הייחודי של yield:

לעומת זאת, yield הוא פקודה ייעודית שנוצרה אך ורק עבור switch expressions. היא אומרת ל-Java: אל תצאי מהמתודה! רק תעבירי את הערך הספציפי הזה החוצה אל תוך המשתנה שמחכה בתוצאת ה-switch, ותני למתודה להמשיך לרוץ רגיל.
